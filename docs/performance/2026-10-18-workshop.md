# Workshop rendering checkpoint — 2026-10-18

## Change and result

The old Workshop invalidation key included every project and every mission's completion. Its geometry only used the selected project's build stage. Renaming another project or completing an unrelated mission therefore discarded and reconstructed the selected building, including procedural materials.

`workshopAppearance` now resolves active project identity and visible stage. `updateWorkshopModel` retains the exact Group, geometries and materials when the stage stays equal, including project switches; it updates interaction identity in place. Real stage changes still create one model, apply world-owned natural maps and dispose the old model. React supplies save and selection in the same update and constructs the initial selected build directly. No save format, XP or persistence behavior changed.

*Zero reflects browser clock resolution, not zero work. These are single-run local measurements of `engine.update`, excluding React, persistence, input handling and the next rendered frame. They quantify removed model construction, not an FPS multiplier.

## Method and environment

- Starting renderer: `ea63dcd` on main, with canvas build/identity/resource diagnostics added before measuring the original invalidation path. The after run uses this checkpoint's selector/reuse implementation. The fixture's initial-selection argument and status text were refined afterward without changing the measured update path.
- Windows 10/Win64 user agent, Chrome 155.0.0.0 in the Codex in-app browser, Three.js r186. Physical GPU/driver identity was not captured.
- Fixed 1280×640 CSS rendering surface, Daybreak, camera reset before each 12-second slow cinematic orbit segment. This is a fixed segment, not a complete 360-degree tour. Browser/provider scheduling and display cadence affect the results.
- Deterministic world: two active projects with four shared tasks each; sixteen unrelated missions, eight initially completed with alternating Craft/Curiosity assignments; all story fragments and a lit beacon. Both selected build stages initially equal 1. No browser saves are read or written by the fixture.
- The synthetic workload renames the other project and toggles one unrelated mission's completion 40 times, synchronously. The chosen mission does not change a garden stage. This deliberately stresses invalidation; it is not a new undo-completion product feature.
- Waited for all four natural material sets, then recorded actual canvas diagnostics and visible JSON using browser controls. No CPU-heavy verification jobs ran during the timed frame samples.
- Raw reports: [baseline](workshop-baseline.json), [optimized](workshop-after.json), [ten renderer cycles](workshop-cycles.json). UUIDs are per-run model identities; they are not persisted progress IDs.

These are `requestAnimationFrame` intervals, not GPU query times or certified sustained frame rates. The modest Quality difference is not evidence of improved steady-state rendering: the optimization targets save updates, and the frame sample has no edits. Reflected and non-reflected frames are included. Optimized Quality ranged from 393–609 renderer calls and 899,640–1,397,628 submitted triangles across passes; Eco ranged from 215–217 calls. These are rendered-pass counters, not unique scene polygon counts.

The initial populated Quality world settled at 43 textures and 210 geometries in this fixture. All ten dispose/remount cycles returned to those counts with one canvas and one initial Workshop build. Current-renderer counters cannot establish process-wide memory reclamation; resource ownership/disposal also has automated regression coverage. Stage 2 appropriately increased this fixture's resources to 45 textures/216 geometries, while another completion within stage 2 retained its model.

All twelve current maps still load in Eco. Source files total 9,377,462 bytes. Resource timing reported 3,600 transferred bytes in the frame runs because assets were already cached/revalidated; the after run reported zero encoded body bytes. These are **warm-cache observations**, not reduced download sizes. No photographic asset conversion or delivery change is included here.

## Actual app verification

On the disposable `localhost:5173` origin, file-input preview/restore loaded a deterministic QA world with 200 XP. Same-stage alpha → beta selection updated project identity while retaining the exact model. An unrelated completion and a shared-task rename retained it. Completing the selected task changed stage 1 → 2 once; the next task stayed stage 2 with the same model. Project renaming updated the island title without rebuilding. Visiting Workshop opened the selected renamed project with its shared completions. Archiving it selected active alpha and replaced the model once for its different stage. Three explicit mission completions brought XP to exactly 275, retained through reload.

Classic → 3D, natural material readiness, one-canvas state and browser errors were checked after those actions. The owner's `127.0.0.1:5173` world was not changed. Five added regression tests cover exact geometry/material reuse, selection/fallback, all stage boundaries, completed-build expansion and no save/XP mutation. Full suite: 86 passing tests; production build and strict lint pass. Vite retains its existing large-3D-chunk warning (about 184 KB gzip).
